Jamf is not an island because the product is closed. It is an island because we never gave anything else a key. Slack, Notion, Mintlify, KMicro, and Cursor all stop at a browser tab. That is why it feels like wasted potential: Protect is doing the job, and none of the rest of the stack can see it.

## Why Cursor never saw it

This Cloud Agent session has Slack, Drive, Notion, Mintlify, GitHub. It does **not** have Jamf. Zapier has no Jamf app. There is no first-party "live inventory" MCP from Jamf.

Jamf ships an official MCP at `https://developer.jamf.com/mcp`. That server searches **Jamf developer docs and API specs**. It cannot list Intertrend Macs, read Protect alerts, or tell you who is off FileVault.

A live tenant connection is a **separate** thing: an API Role \+ API Client in Jamf Pro, then a local MCP (community [JamfMCP](https://github.com/liquidz00/jamfmcp), or a thin wrapper we write) pointed at `intertrend.jamfcloud.com`. That is how a new Cursor agent actually works the fleet.

Setup: [Connect Cursor to Jamf](/jamf/connect-cursor).

## What a connected agent is for

Once Cursor has a **read-only** API client:

- "Which Macs are off FileVault or not checking in?"
- "Who is still on Ventura?"
- "What is scoped to the Wi-Fi profile?"
- "Draft the next health-check delta against March 2026"
- "Open a ticket list for Protect stale records"

Write access comes later, if ever. An agent that can create policies without you in the loop is how we get a surprise config. Read first.

Do not put the API client secret in Slack, Drive, or this site. Cursor MCP settings or 1Password only.
